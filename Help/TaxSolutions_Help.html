1. Purpose and navigation

TaxSolutions converts bank statement CSV exports into a common format. The tabs are Master, Revolut, Halifax, Volksbank, Excluded merchants and Configuration.

Use the question-mark button on any tab to open this offline guide in your default browser. Use Ctrl+F to search and Ctrl+P to print or save a PDF. The guide requires no internet connection.

Description replacements and dual currency exports (Revision 021)

After checking original descriptions against enabled exclusions, all bank converters standardise descriptions ignoring case. Any complete description containing the substring Frankfurt Flugha becomes Flughawe Frankfurt followed by one space, ignoring case. For example, 61010113 Frankfurt Flugha is replaced in full. Exact LNK HUNTINGDON becomes HUNTINGDON OSTEOPA, ignoring case and surrounding whitespace. JULIAN ANDRE LE FR is a new enabled shared exclusion phrase, checked against the original description across all bank converters; it can be managed on Excluded merchants. Exact SURVEY SUPPLIES LI becomes SURVEY SUPPLIES IRELAND; exact Deutsche Post AG becomes DE Pension: Deutsche Post AG. Both matches ignore case and surrounding whitespace. Exact AMZNMktplace becomes Amazon. Exact WWW.HEATHROWEXPRESS.CO becomes Heathrow Express; exact OPENAI *CHATGPT SUBSCR becomes OpenAI ChatGPT. Any description containing AMZN Mktp becomes Amazon, containing eBay becomes eBay, or containing LUFTHAN becomes Lufthansa, including a concatenated reference such as LUFTHAN2204102769195. Volksbank credit-card descriptions are split at three or more spaces before these replacements. The final descriptions determine sorting, followed by transaction date.

Every separate Income export (Halifax, Revolut and Volksbank) now has Transaction Date, blank, Transaction Description, Credit (GBP), Credit (EUR), Conversion Factor, Source Bank. Every separate Expenses export uses Debit (GBP) and Debit (EUR) in the corresponding positions. Source-currency values are retained; GBP sources multiply by the saved monthly GBP-to-EUR factor to obtain EUR, while EUR sources divide by it to obtain GBP. Amounts are positive, formatted to two decimals; monthly factors use six decimals. Factors are required for GBP income as well as every other converted category. The existing combined Deutschebank export retains its established Credit/Debit/Currency layout.

2. Configuration workflow

  1. Open Configuration.
  2. Select the report year and From/To months.
  3. Review the monthly factors in all three currency cards.
  4. Choose Save Configuration and check Comments for confirmation.
  5. Open the appropriate bank tab, browse to its CSV export and use its conversion button.

3. Excluded merchants

This tab sits immediately before Configuration. One shared list applies to original transaction descriptions in every implemented bank converter, including Halifax, Revolut and DeutscheBank, and the retained credit-card conversion. Volksbank remains an unimplemented converter.

Every checked entry uses the same rule: the description must contain the complete contiguous phrase, ignoring case. There is no transaction-type restriction. For example, Julian Gray excludes To Julian Gray. The phrase e.on matches E.ON literally; the dot is not a wildcard. Matching happens before description prefixes or punctuation are removed.

Checkboxes

Checked means exclude. Untick an entry to disable that phrase. Another checked phrase can still exclude the row: disabling Julian Gray does not disable a separately checked Julian Gray Land Surveyor entry. Normal bank-specific transaction-type, date and validation rules still apply. Existing exported files change only when you convert again.

Merchant / Phrase card

  1. To add a merchant, type a new or modified phrase in the Merchant / Phrase card below the grid and choose Add. This creates a separate entry; the previously selected phrase is retained. New entries are checked by default.
  2. To replace an existing phrase, select its row, edit the text field and choose Save. Save overwrites that selected entry, retaining its checkbox state. Edit focuses the text field and does not save changes.
  3. To delete a merchant, select its row and choose Delete.
  4. Checkbox changes save automatically. Add, Save and Delete persist their respective changes immediately. Typing in the text field or choosing Edit does not save changes. Read Comments for confirmation or a failure message.

Blank phrases and duplicate phrases (ignoring case) are rejected. Deletions and edited phrases survive restart; deleted built-in entries do not reappear. The four new checked defaults are Bayerischer Rundfunk, e.on, Julian Gray and Julian Gray Land Surveyor.

Saved settings

The shared list is stored in TaxSolutions.merchants.json beside the application. Earlier checkbox files are read without being overwritten at startup, and their checked/unchecked choices are retained. On the next successful change, the editable list is saved in its updated format. Newly introduced defaults are added without resetting existing choices.

A failed save restores the previous active list or checkbox and reports the error in Comments. A failed Add or Save also retains the selected row and typed text so it can be corrected or retried. If the saved list cannot be read, default phrases remain active and Comments reports the issue; the saved file is left untouched. Save Configuration is not required for merchant changes.

4. Report Time Period

The default year is 2026, with January through March initially selected. Choose one to three consecutive months within the selected year. The To month must not precede the From month. Month labels on all three cards follow the selected period; unused fields are disabled.

5. Monthly conversion factors

CardFactor definition
Conversion factor: GBP to EUREUR per 1 GBP
Conversion factor: GBP to ZARZAR per 1 GBP
Conversion factor: EUR to ZARZAR per 1 EUR

Every factor without a saved value defaults to 1.000000. Existing saved values are retained. Each pair has up to three monthly entries.

Factors are positive decimal values, stored and displayed to six decimal places. A decimal point or comma is accepted; thousands separators are not. Extra precision is rounded to six places, with midpoint values rounded away from zero.

A default of 1.000000 means a one-for-one conversion. Review and enter the intended monthly rates before relying on currency-converted reports.

Each factor expresses destination currency per one unit of source currency. For example, GBP 100 multiplied by a GBP-to-EUR factor of 1.170000 gives EUR 117. Halifax EUR expenses use this multiplication with the factor for each transaction month, rounded per transaction to two decimal places (midpoints away from zero).

6. Save Configuration and stored settings

The Save Configuration button sits below the three conversion cards. It saves the report period and monthly factors for all three pairs in TaxSolutions.settings.json beside the application. Saved rates reload at startup; entries for other previously configured months are retained.

Default values appear automatically but are written to disk only when Save Configuration is selected. Invalid entries do not replace the saved configuration. If settings cannot be read or written, Comments reports the problem. The application needs write access to its folder to save settings.

7. Revolut bank statements

Bank statement CSV files can only be downloaded through the desktop link, not through the phone app.

  1. Save Configuration with the report period and monthly GBP-to-EUR factors.
  2. On Revolut, select the EUR CSV in the first selector and GBP CSV in the second.
  3. Choose Convert Revolut to combine both sources into Income and Expenses.

An incorrect header or currency selection warns: This is not a Revolut EUR/GBP file. The exact required header is Type,Product,Started Date,Completed Date,Description,Amount,Fee,Currency,State,Balance. Line 2 of the EUR source must contain ,EUR,; line 2 of the GBP source must contain ,GBP,. Every parsed record must have the matching Currency. Select both source files; they may be in different folders. Tab changes clear both displayed selections while Browse retains the last accessed folder.

Exclusions and description changes

The shared Excluded merchants list applies before any description normalization, using the same case-insensitive complete-phrase contains rule as the other banks. Existing merchant names and private-transfer/deposit descriptions remain in the list and can be edited, deleted or unticked. Their earlier transaction-type restrictions no longer apply. The earlier Exchange entry is now the description phrase Exchange; it does not independently test the Type column.

After exclusions, leading Payment from and To phrases are removed (whole phrases at the beginning only). Words such as Tokyo remain unchanged. Metal plan fee becomes Bank charges. State is not filtered, and Fee is not separately added or deducted; Amount is used as supplied.

Classification and conversion

Started Date determines the transaction date and saved-period filtering. Positive Amount values enter Income. Negative values enter Expenses as positive debits. Zero-value rows are omitted and counted. Values outside the saved report months are excluded.

Source and outputCalculationConversion Factor column
GBP incomeOriginal GBP credit; EUR credit = GBP × monthly factorSaved monthly factor
EUR incomeOriginal EUR credit retained; GBP credit = EUR divided by monthly GBP-to-EUR factorSaved monthly factor, used as divisor
GBP expenseOriginal GBP debit; EUR debit = GBP × monthly factorSaved monthly factor
EUR expenseGBP debit = EUR ÷ monthly factor; original EUR debit retainedSaved monthly factor, used as divisor for GBP

Converted money values round to two decimal places, with midpoints away from zero. The saved factor is never replaced by a rounded reciprocal. Factors are written with six decimals. Rows from both files are combined and sorted by description then date.

Output files

Both files are written in the EUR source file’s Converted folder, created when needed. For July–September 2026:

  • Revolut_Income_2026-07-01_2026-09-30.csv
  • Revolut_Expenses_2026-07-01_2026-09-30.csv

The filename date range comes from the saved report period. Output columns match Halifax, described below. Existing outputs with the same names are replaced only after both input files and required rates pass validation.

8. Halifax bank statements

  1. Save Configuration with the required report year, From/To months and monthly GBP-to-EUR factors.
  2. Open Halifax, browse to the source CSV and select Convert Halifax.
  3. Check the completion message and Comments for both output paths and transaction counts.

The converter uses saved settings; unsaved Configuration edits do not affect a report. All eight headers are required: Transaction Date, Transaction Type, Sort Code, Account Number, Transaction Description, Debit Amount, Credit Amount and Balance. Missing, duplicate or extra headers produce a warning: This is not a Halifax file The column order may vary. Input dates use day/month/year.

Exclusions and classification

Checked phrases from the shared Excluded merchants list are applied to the original description first.

  1. Exclude TFR and SO transactions.
  2. Exclude FPO only when Transaction Description equals JULIAN ANDRE LE FR.
  3. Exclude transactions outside the saved report period, including its complete first and last months.
  4. Write FPI income and other positive credits, including refunds, to GBP Income.
  5. Write remaining positive debits to Expenses with both GBP and EUR amounts.

OUR CHARGE becomes Bank charges. Other descriptions are retained. Every export sorts by Transaction Description (case-insensitive), then transaction date across the whole report period; there is no monthly grouping. Zero-value rows are omitted and counted. Rows with both a positive debit and credit, negative amounts, or an FPI debit without a credit are rejected for review.

Output names and columns

Files are written in the Converted subfolder of the source folder; the application creates it when required. For Halifax_GBP_2026-07-01_2026-09-30.csv, the outputs are:

  • Halifax_Income_2026-07-01_2026-09-30.csv
  • Halifax_Expenses_2026-07-01_2026-09-30.csv

The source name must contain exactly one GBP token separated by underscores. Both export layouts now have seven columns. Income: Transaction Date, blank, Transaction Description, Credit (GBP), Credit (EUR), Conversion Factor, Source Bank. Expenses: Transaction Date, blank, Transaction Description, Debit (GBP), Debit (EUR), Conversion Factor, Source Bank. Column G is the source bank: Halifax, Revolut or Volksbank. Amounts occupy columns D (GBP) and E (EUR), factor F and source bank G. Debit (GBP) retains the original GBP debit; Debit (EUR) contains its converted EUR value. Both outputs have headers. Halifax income and expenses both use the saved monthly GBP-to-EUR factor: EUR equals original GBP multiplied by that factor. Dates use yyyy-MM-dd. GBP amounts are written to two decimal places.

EUR expenses equal each GBP debit multiplied by its transaction month’s saved GBP-to-EUR factor, rounded per transaction to two decimal places with midpoints away from zero. Missing or invalid required factors stop conversion before exports are written. Commas, quotes and multiline descriptions are correctly quoted in CSV output.

Both files are created, including header-only files when a category has no rows. Comments and the completion dialog retain the full result: completion on its own line, report period, counts, a single save-folder line and the two filenames below. The dialog widens to fit the text; wrapping is disabled and horizontal scrolling is available for exceptionally long paths. Closing it does not clear Comments. Source and configuration are validated before output files are replaced. Temporary files and rollback backups are used during publication; close exports in Excel before converting again.

9. Volksbank and Deutschebank

Volksbank: select Giro CSV and Credit Card CSV. Both files are required and must be different. German format defaults to checked: semicolon separator and decimal comma. Unchecked means comma separator and decimal point. Changing this option clears both selections so they can be validated again. Amounts accept an optional leading sign and up to two decimals; thousands separators are rejected to avoid ambiguous interpretation. UTF-8 and Windows-1252 exports are supported. The first column must contain VR-Girokonto Online somewhere in the Giro file and Kreditkartenkonto somewhere in the card file. Swapped or unrecognised files are rejected.

Transaction headers may follow introductory account rows. Column E must be Buchungstag and L Betrag. Giro column G is Name Zahlungsbeteiligter. Card column K is Verwendungszweck (the supplied spelling Verwendingswek is also accepted). Dates accept dd.MM.yyyy, yyyy-MM-dd or dd/MM/yyyy with an optional single-digit day/month. Nonblank malformed transaction rows stop conversion before existing exports are changed.

Volksbank skips any transaction with Julian Andre Le Fraper Gray anywhere in its fields, ignoring case. It also skips a trimmed description equal to meine Volksbank Raiffeisenbank eG (after card merchant extraction). Blank or whitespace-only descriptions become Volksbank bank charges. All source amounts are EUR. Negative amounts become positive expenses; positive amounts become income; zeros are skipped. Card rows are skipped when column J contains Gutschrift and column K contains Abrechnung vom. Card descriptions use the trimmed first part of K before three or more consecutive ordinary spaces; single and double internal spaces remain. Shared enabled merchant phrases are matched against the original description, ignoring case. Only transactions in the saved report period are exported.

GBP = absolute EUR amount divided by the transaction month's saved GBP-to-EUR factor, rounded to two decimals away from zero. Expenses retain original EUR in Debit (EUR); income retains original EUR in Credit (EUR) alongside computed Credit (GBP). Conversion Factor shows the monthly factor to six decimals; Source Bank in column G is Volksbank. Both sources combine into Volksbank_Income_{from}_{to}.csv and Volksbank_Expenses_{from}_{to}.csv using full saved report dates yyyy-MM-dd, in the Giro file's Converted subfolder. This remains the destination even when the card file comes from another folder. Both files are created, including header-only categories. Rows sort by description then date. Publication uses the same validation, locking checks and rollback handling as Halifax and Revolut. Comments retain the full completion summary.

The Deutschebank tab is hidden; its existing conversion source is retained. The credit-card button has been removed from Configuration.

The Deutschebank conversion retains its existing amount columns, adding Source Bank in column G: Booking date, Invoice, Beneficiary / Originator, Credit, Debit, Currency and Source Bank. The bank label is DeutscheBank. Halifax uses the Income and Expenses layouts described above. All bank exports sort by description and then date. Changing tabs clears the displayed input path. Browse opens in the last selected folder, which is retained across application restarts. The last full selection and Browse folder are stored separately in TaxSolutions.files.json beside the application; a remembered path is not automatically selected for conversion.

An existing output file with the same name is overwritten. Each converter requires its bank-specific export format. For Halifax, malformed rows or invalid values are reported before exports are replaced.

11. Detailed bank workflows

Conversion buttons are disabled until valid source files have been selected in the current tab: Revolut requires its EUR and GBP files; Volksbank requires Giro and Credit Card files; Halifax requires its single CSV. Selection checks verify bank headers/account markers and currency where applicable. Detailed transaction validation still runs during conversion. Switching tabs clears selections and disables conversion again; changing Volksbank format also clears both files. The merchant editor button order is Edit, Add, Delete, Save, with the established workflow unchanged.

11.1 Prepare the report

  1. Open Configuration. Select the year and From/To months (one to three consecutive months). Enter the GBP-to-EUR factor for each month as EUR per GBP; for example 1.250000 means GBP 1 equals EUR 1.25.
  2. Click Save Configuration. Confirm success in Comments. Conversion always reads saved settings; merely changing fields does not change an export.
  3. Open Excluded merchants. Checked phrases exclude matching original descriptions, ignoring case and matching the complete phrase anywhere in the description. Add creates a separate phrase, Edit prepares the selected phrase, Save overwrites it, Delete removes it. Overlapping enabled phrases still apply. Checkbox choices save immediately.
  4. Keep source statements intact. Close existing converted files in Excel before regenerating them. Each conversion replaces matching export names after validating the sources.

11.2 Revolut: two source statements to two exports

  1. Download separate EUR and GBP statement CSVs through the desktop link; the phone app does not provide the required downloads. Include the saved report months.
  2. Open Revolut. Browse EUR CSV first, then GBP CSV. They must be different files. The exact header is Type,Product,Started Date,Completed Date,Description,Amount,Fee,Currency,State,Balance. Physical line 2 must contain ,EUR, or ,GBP, respectively. Each record must have the corresponding Currency. Wrong selections warn This is not a Revolut EUR/GBP file.
  3. Click Convert Revolut. Started Date controls period inclusion; positive Amount becomes income, negative becomes a positive expense, zero is skipped. Enabled excluded phrases are checked before leading Payment from / To removal and description replacements. Metal plan fee becomes Bank charges. State is not filtered; Fee is not added or subtracted separately.
  4. Review both currencies: GBP source amounts retain GBP and multiply by the monthly factor for EUR; EUR source amounts retain EUR and divide by that factor for GBP. Converted amounts round to two decimals, factors to six.
  5. Read Comments and the completion dialog. Locate Revolut_Income_{from}_{to}.csv and Revolut_Expenses_{from}_{to}.csv in the EUR source file's Converted folder, even when the GBP source came from another folder. Full dates use yyyy-MM-dd and come from Configuration.

11.3 Halifax: one GBP statement to two exports

  1. Use a Halifax CSV with Transaction Date, Transaction Type, Sort Code, Account Number, Transaction Description, Debit Amount, Credit Amount and Balance. All eight headers must exist exactly once; their order can vary. Invalid headers warn This is not a Halifax file.
  2. Ensure the source filename contains one underscore-separated GBP token, for example Halifax_GBP_2026-07-01_2026-09-30.csv. Open Halifax and Browse to the source. Input dates are day/month/year.
  3. Click Convert Halifax. Only saved report months are included. TFR and SO are ignored, and FPO with description JULIAN ANDRE LE FR is ignored. Shared merchant exclusions apply to the original description. OUR CHARGE becomes Bank charges.
  4. Positive Credit Amount goes to Income, including FPI income and refunds; positive Debit Amount goes to Expenses. A row with both positive values, a negative amount or FPI debit without credit is rejected. Zero amounts are skipped. Each amount retains GBP and is multiplied by its saved monthly factor for EUR.
  5. Open the source folder's Converted subfolder. Output names replace GBP in the source name with Income and Expenses: Halifax_Income_2026-07-01_2026-09-30.csv and Halifax_Expenses_2026-07-01_2026-09-30.csv. Unlike Revolut and Volksbank, Halifax's filename dates follow its source filename; for Master, these names must match the saved report dates.

11.4 Volksbank: Giro and Credit Card to two exports

  1. Open Volksbank. Leave German format checked for semicolon-separated data with decimal commas. Untick only for comma-separated data with decimal points. Changing this option clears both inputs for revalidation. Thousands separators are rejected rather than interpreted ambiguously.
  2. Browse Giro CSV and Credit Card CSV. Both are required and must differ. The first column somewhere in Giro must contain VR-Girokonto Online, and somewhere in Credit Card Kreditkartenkonto. Introductory account rows before transaction headers are allowed. UTF-8 and Windows-1252 files are supported.
  3. Check transaction columns: E Buchungstag, L Betrag, Giro G Name Zahlungsbeteiligter, Card K Verwendungszweck (the supplied spelling Verwendingswek is also recognised). Dates can be dd.MM.yyyy, yyyy-MM-dd or dd/MM/yyyy. The card's description is trimmed text before three or more consecutive spaces; single/double spaces inside a name remain.
  4. Click Convert Volksbank. Source currency is EUR: negative values become positive expenses, positive values income and zero values are skipped. Saved report dates apply. Card rows with J containing Gutschrift and K containing Abrechnung vom are skipped. A transaction containing Julian Andre Le Fraper Gray anywhere in its fields is skipped. A description equal to meine Volksbank Raiffeisenbank eG is skipped. Blank descriptions become Volksbank bank charges. Shared merchant phrases still exclude original descriptions.
  5. Review GBP as EUR divided by the saved month factor, rounded to two decimals. Original EUR remains unchanged in its amount column; factor uses six decimals. Standard merchant replacements apply after card-name extraction, including AMZNMktplace to Amazon.
  6. Find Volksbank_Income_{from}_{to}.csv and Volksbank_Expenses_{from}_{to}.csv in the Giro source file's Converted folder, even when the card file is elsewhere. Dates come from the saved Configuration period.

11.5 Review every bank output

Income columns A–G are Transaction Date, blank, Transaction Description, Credit (GBP), Credit (EUR), Conversion Factor and Source Bank. Expenses use Debit (GBP) and Debit (EUR) in D/E. All dates are yyyy-MM-dd. Amounts are positive and have two decimals; factors six. Rows sort by final description, ignoring case, then date. Header-only files are valid when a category has no transactions. Comments retain the result after the completion dialog closes. Bank CSV text fields show filenames only. Full selected paths are recorded in Comments and retained internally for conversion. Changing tabs clears selected filenames, while Browse remembers the last accessed folder across tabs and restarts. If that folder is missing or unavailable, Browse starts at C:\\ and Master displays C:\\Converted.

12. Master combined reports

  1. Save Configuration for the intended report period, and convert Revolut, Halifax and Volksbank using that period.
  2. Place all six bank export files together in one Converted folder. Each bank normally writes beside its designated source; when these are different folders, copy the generated Income and Expenses CSVs into the common folder. Keep source bank filenames intact and make sure their dates match the saved full-month range.
  3. Open Master, the first tab. Converted folder displays the automatic destination: the last bank Browse folder plus Converted. If the remembered folder is already named Converted, it is used directly. Use Browse on the Converted folder card to select a different folder when required. This explicit folder is used directly (without appending Converted), retained across tabs and restarts, and is not replaced by subsequent bank file browsing. If the selected folder becomes unavailable, the automatic retained-folder/C-drive fallback applies.
  4. Click Generate combined CSV files. Master checks Revolut_Income_{from}_{to}.csv, Halifax_Income_{from}_{to}.csv and Volksbank_Income_{from}_{to}.csv. If any are absent, it lists their names and offers Proceed or Cancel. Proceed permits partial income; Cancel stops without changing combined files.
  5. It separately checks the equivalent three Expenses files. Missing files produce a second Proceed / Cancel prompt. Cancel here also leaves both existing combined files unchanged. Proceed for an entirely missing category produces a header-only combined file for that category.
  6. Available source files must use the current seven-column layout, valid dates within the saved period, positive conversion factors, two-decimal nonnegative amounts, six-decimal factors and the correct bank label. Reconvert a bank if an old header is rejected. Existing combined exports are never treated as source files.
  7. Master combines all available Income records and all available Expenses records. It preserves both amounts, the recorded factor, description and source bank. It does not recalculate currency, apply exclusions again or remove duplicate transactions. Both combined files sort by description and then date.
  8. Read Comments and the completion dialog. Combined_Income_{from}_{to}.csv and Combined_Expenses_{from}_{to}.csv are saved directly in the selected folder. Matching combined files are replaced with the shared locking checks and rollback protection. Comments list any missing files you elected to omit.

Deutschebank is hidden for the present workflow. Its existing conversion source is retained. The visible tab order is Master, Revolut, Halifax, Volksbank, Excluded merchants, Configuration.

Proceed means the combined report may be incomplete. Check the listed omissions and source-bank totals before using the result.
